# Forge Console — Fix Brief 11 (2026-10-04): C6 tokens_today

One-line-ish fix. `collector.py` `get_harnesses` still hardcodes
`"tokens_today": 0` for `harness-c6` (line ~286). The user sees "today's tokens: 0".

Fix — populate it like the other three harnesses, but from the C6 source.
The three others call `http://127.0.0.1:8901/api/<opencode|claudecode|antigravity>?days=1`
and read `data["total"]["input_tokens"] + data["total"]["output_tokens"]`.

C6's source is DIFFERENT (verified live): `http://127.0.0.1:8901/api/summary?days=1`
returns a TOP-LEVEL shape (no `total` sub-object), e.g.
`{input_tokens:1586952, output_tokens:300061, cache_read_tokens:..., billed_tokens:...,
sessions:8, ...}` — a rolling 24h window. So for C6:
- `tokens_today = data["input_tokens"] + data["output_tokens"]` (NOT `data["total"][...]`).
  If `days=1` isn't strictly calendar-today, that matches how the other three already
  use `?days=1`, so it's consistent — no need to re-derive a window.
- Same pattern as the others: `urllib.request` GET, `timeout=0.8`, `User-Agent:
  ForgeConsole/1.0`, wrapped in try/except → `tokens_today = 0` on ANY failure
  (missing endpoint, timeout, bad JSON). Never raise, never block the collector.
- Put the fetch right where the C6 block assembles its dict, so it reuses the same
  `now`/context the other harnesses use.

Verify:
- `python3 -m py_compile collector.py` clean.
- The collector change needs a service restart — do NOT run it yourself; STOP and
  note "restart pending" in your report (C6 fires `systemctl --user restart
  forge-console`).
- After the restart (C6 will confirm): `/api/flow` `harness-c6` should show a
  non-zero `tokens_today` matching roughly `input+output` from
  `/api/summary?days=1` (they can differ slightly by timing — that's fine).
- Do NOT change the other three harnesses or anything else.
- End with a one-line report: the endpoint + field mapping you used, and the
  "restart pending" note.
