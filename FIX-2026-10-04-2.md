## Item 1 — opencode daemon counted as an active harness
Symptom: the opencode harness node shows running/active all the time, even with no
agent running.
ROOT CAUSE (diagnosed — verify): `scan_processes_by_name()` in `collector.py` matches
any process whose exe is `opencode` or whose path contains `/bin/opencode`. The
persistent background daemon `/home/bsmt-pc/.opencode/bin/opencode serve --service`
(matching pid currently 80120) satisfies that, so `found["opencode"]` is never empty
and `harness-opencode.running` is always true.
FIX: in the opencode branch of `scan_processes_by_name()`, skip the process when its
args contain the daemon marker — e.g. `parts[1] == "serve" or "--service" in parts`
(or simply `if "serve" in parts and "--service" in parts: continue`). Keep the
matching for real runs (`opencode run ...`, `opencode serve` without --service is the
daemon too — the daemon is specifically `serve --service`). Everything else in the
claude/agy/hermes branches stays as-is. The DB-based `active_sessions`/`subtasks`
logic is already correct — do not touch it.
VERIFY: with only the daemon running, `python3 -c "import collector; p=collector.scan_processes_by_name(); print(p['opencode'])"` → `[]`; and a real `opencode run` process (you can spawn `timeout 20 ~/.opencode/bin/opencode run hi` in the background while testing) DOES show up. Then restart the unit and confirm `/api/flow` harness-opencode `pids` == `[]` and `running` == false (given no real run active at check time).

## Item 2 — project nodes overlap
Symptom: ~14 project nodes pile on top of each other in the left column.
ROOT CAUSE (diagnosed — verify): `buildFlowGraph()` places projects on an arc
(angle 0.8π→1.2π, radius 380). Total arc length ≈ 477px spread over 14 nodes ≈ 34px
pitch, but each project node is ~190×48 — guaranteed heavy overlap.
FIX: replace the arc with a clean vertical column on the left:
- Compute a pitch that guarantees zero overlap for any project count:
  `pitch = Math.max(58, Math.min(80, (height - 140) / Math.max(1, n)))` (tune to
  taste — the requirement is: zero bounding-box overlap for up to ~18 projects, and a
  pleasant centered column when there are few). Center the column vertically on `cy`.
- Keep one column (no 2-column grid — the user wants it to look like the data-stores
  stack, item 3).
- x position: keep it clear of the FILESYSTEM node (cx - 360) — the projects column
  should sit at roughly cx - 520 (or whatever keeps nodes fully on-canvas; clamp so
  nodes don't leave the visible area at 1280px width).
- Edges from FILESYSTEM → each project stay, just updated endpoints (they use node
  positions, so this may be automatic).
VERIFY: in the browser, collect all project node bounding boxes and assert every pair
is disjoint (write a small JS check in the browser console via the canvas state if
exposed, or geometrically from the layout math at 1280×800 and at 1920×1080).
