## Part 2 — server.py binds three ports (one process)

In `server.py` main(): after the existing 8903 `ReusableThreadingServer` is created,
spin up two more ThreadingHTTPServer instances in daemon threads:

- 8901: the insights engine's handler class. Load the engine with importlib under a
  UNIQUE module name to avoid the `server.py` filename collision with the console's
  own __main__:
    import importlib.util
    spec = importlib.util.spec_from_file_location("insights_engine", str(BASE_DIR/"insights/server.py"))
    insights_engine = importlib.util.module_from_spec(spec); spec.loader.exec_module(insights_engine)
  Use `insights_engine.Handler` (verify the actual class name in insights/server.py).
- 8902: same pattern for `ideas/server.py` under name "ideas_engine", using its
  `SchemeBoardHandler` (verify actual class name). BEFORE loading ideas_engine,
  `sys.path.insert(0, str(BASE_DIR/"ideas"))` so its `from db import ...` resolves.
- Each engine server: `ThreadingHTTPServer.allow_reuse_address = True`, bind
  ("0.0.0.0", port), served via `srv.serve_forever()` inside its own daemon thread.
- Do NOT call the engines' main()/run_server() (they'd block). Only their Handler
  classes are used.
- Keep the console's existing transparent /api/* proxy routes to
  http://127.0.0.1:8901 / :8902 EXACTLY as they are — they now hit the in-process
  engine servers on localhost. Do not attempt direct in-memory dispatch.
- The engine files already contain the round-15 root-redirect behavior (8901/ `/`
  and `/index.html` → 302 to 8903/#/insights and 8903/#/ideas) — do not remove it.
- Startup order: start engine servers (8901, 8902) BEFORE the collector thread,
  so the collector's first `/api/summary` etc. find them listening. Handle a port
  already in use at startup (old standalone service not yet stopped) with a clear
  error message in the log and re-raise (fail fast, don't half-start).
