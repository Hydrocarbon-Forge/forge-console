# Forge Console — Fix Brief 12 (2026-10-04): C6 "running" label

Web-only. File: `web/app.js` (the harness detail/tooltip body, ~lines 3068-3077).

Problem: for the C6 (Hermes) harness node, the status subline reads
`h.running ? "IDLE (Gateway Running)" : "IDLE"` when `active_sessions == 0`.
Because the hermes gateway process is ALWAYS up, `h.running` is permanently true,
so the C6 node is perpetually described as "Gateway Running" — which reads like the
harness is actively running even when nothing is happening. The user wants C6 to only
appear "running" when it's actually doing work.

Fix (C6-specific; do NOT change the other three harnesses, whose `running`
legitimately means "a process is present"):
- C6 status text when `active_sessions > 0`: `ACTIVE (N Sessions)` (unchanged).
- C6 status text when `active_sessions == 0`: just `IDLE` — drop the
  "(Gateway Running)" suffix entirely. The gateway being up is not "running work".
  (Keep the tooltip's `last active: Xs ago` field for context — that's fine.)
- The node body lit/glow + hub-edge dots are ALREADY activity-gated (round 10:
  `running && (active_sessions>0 || last_active_s<300)`). Do NOT change that logic —
  it correctly dims when idle. Only the label changes.
- HUD "N Active" counter (line ~1858) uses `active_sessions>0 || h.running`, which
  counts C6 as always-active (since running is always true). If you confirm it makes
  C6 always count as "active", align C6's contribution to the SAME activity test
  used for the node body (`running && (active_sessions>0 || last_active_s<300)`).
  Leave the other harnesses' contribution as-is. Only change it if it demonstrably
  over-counts C6.

Verify (live browser, user's real ~1280x525 canvas):
- While chatting: C6 node shows `ACTIVE (N Sessions)` and is lit.
- When idle (no active sessions): C6 node shows `IDLE`, is dim, no dots, and the
  tooltip no longer says "Gateway Running".
- Other three harnesses unchanged.
- `node --check web/app.js` clean.
- Web-only: no service restart needed or run.
- End with a one-line report: the exact label changes + whether the HUD counter
  needed aligning.
