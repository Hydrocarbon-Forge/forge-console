## Item 1 — KPI cards (tokens / cache re-reads / sessions / tool calls) must follow the source picker

ROOT CAUSE (verified): `handleSourceSelect(src)` (app.js ~line 79) only calls `renderCost(lastCost)`, `updateCostHeadline()`, `refreshKPIOnly()`, `renderFlowForSource()`. `refreshKPIOnly` ONLY updates the EST. COST/D card (`kpis[5]`). The other 5 KPI cards (TOKENS BILLABLE, CACHE RE-READS, SESSIONS, TOOL CALLS, CACHE HIT RATE = `kpis[0..4]`) are set ONCE in `render()` from the all-source `d.summary` and are never recomputed when the source changes. So switching source changes cost + flow but the token/session/tool-call/cache KPIs stay at the all-source values.

DATA AVAILABLE (verified via API):
- `lastSummary` (`/api/summary`) = C6/all base: `billed_tokens, input_tokens, output_tokens, cache_tokens, cache_read_tokens, sessions, messages, user_messages, tool_calls`.
- `lastOpencode` (`/api/opencode`), `lastClaudecode`, `lastAntigravity` each return: `sessions` (int), `total:{input_tokens, output_tokens, cache_read_tokens, reported_cost_usd}`, `models:[...]`, `daily:[...]`.
- IMPORTANT: the per-source `.total` does NOT carry `tool_calls`, `messages`, `user_messages`, `billed_tokens`, or `cache_write_tokens`. So for non-C6 sources, TOOL CALLS + the messages sub-line have no data.

FIX: add a `summaryForSource(src)` helper that returns a normalized summary for the selected source:
- `c6` → from `lastSummary` (all fields present).
- `opencode` / `claudecode` / `antigravity` → from `last<Source>`: `sessions = .sessions`, `input_tokens = .total.input_tokens`, `output_tokens = .total.output_tokens`, `cache_read_tokens = .total.cache_read_tokens`, `billed_tokens = sumBilled(.models)` (reuse the existing `sumBilled` helper), `tool_calls = null`, `messages = null`, `user_messages = null`.
- `all` → combine all four by summing `input_tokens`, `output_tokens`, `cache_read_tokens`, `sessions`; `billed_tokens = sumBilled(all models across the four sources)`; `tool_calls` = `lastSummary.tool_calls` (C6's, the only source that has it) — or null if you prefer "—". (Combining token counts across sources is fine; they're independent streams.)
Then in `handleSourceSelect`, after the existing calls, re-render the KPI cards 0–5 from `summaryForSource(src)` (extract the KPI-building block currently in `render()` into a `renderKPIs(summaryObj, costHeadline)` function and call it from BOTH `render()` and `handleSourceSelect`). For fields that are `null`/unavailable for that source (tool_calls, messages), display `—` in the value and keep the sub-line honest (e.g. "tool calls: — (not reported for this source)"). Cache hit rate = `cache_read_tokens / max(1, input_tokens + cache_read_tokens)`.

VERIFY item 1: with the page live, click each source button (C6 / opencode / claude code / antigravity / all). The SESSIONS card changes (C6 vs e.g. opencode=22, claude code=9, antigravity=34 — match the API `.sessions`), TOKENS (BILLABLE) changes per source, CACHE RE-READS changes, and the flow chart header label changes. ## Item 4 — Flow projects stay lit too long (collector.py)

ROOT CAUSE (verified): in `collector.py` `get_filesystem_and_projects()` (line ~393-402), a project is `active = changes_60m > 0` where `changes_60m` counts files with `age < 3600` (60 min). So any write in the last 60 min keeps the project highlighted. User wants projects to STOP highlighting once writes go stale (a write 30–45 min ago should no longer count as "active/being written to").

FIX: 
1. Add a per-project `last_write_age_min` = age-in-minutes of the NEWEST file write (smallest `now - mtime`) for that project (null if no recent files), so the UI can show how stale it is.
2. Introduce a short "active" window constant near the top of `collector.py`, e.g. `PROJECT_ACTIVE_WINDOW_S = 600` (10 min). Set `active` = (newest write age < `PROJECT_ACTIVE_WINDOW_S`), i.e. "written to within the last 10 min" — NOT the 60-min window. Keep `changes_60m` and the `recent_files` list on the 60-min basis (that's the recent-writes context panel) so you don't lose the 60-min data, but drive the Flow highlight/dots from the short window.
3. Update `projects.append({...})` to include `last_write_age_min` and the new short-window `active` (and set `accent` from the short-window `active`).
This makes console/backups/scheme-board stop being lit after ~10 min of no writes, matching the "no recent writes → not highlighted" intent. The Flow dot-direction (dots flow out of the Forge into active projects) is unchanged — only which projects count as active changes.

VERIFY item 4: run `python3 -m py_compile collector.py`. Then hit `8903/api/flow` and confirm `projects[]` entries now carry `last_write_age_min` and `active` reflects the ~10-min window (a project whose newest write is 30–45 min old should have `active:false`). Note the collector caches project scans for 10s, so force a fresh scan if needed (wait >10s or restart isn't required — the next scan re-evaluates).
