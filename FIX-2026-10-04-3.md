# Forge Console — Fix Brief 3 (2026-10-04)

Two design changes to the **Flow tab** (`web/app.js` only). Vanilla JS + canvas, no new
deps, keep the existing code style / IIFE structure. The server is a systemd user unit —
restart with `systemctl --user restart forge-console` (NOT kill/nohup). Do NOT touch the
Insights/Ideas tabs or their backgrounds.

Context: the Flow tab currently renders these node types — `hub` (FORGE HUB), `harness`
(opencode/claude code/antigravity), `filesystem` (FILESYSTEM), `project` (one node per
project, currently ~14 in a vertical column), `service`, and `datastores` (currently a
VERTICAL stack of rows). `buildFlowGraph(doc)` builds the nodes/edges; `drawStoresStack`
renders the current vertical data-stores; `drawSquareNode` renders generic square nodes;
`sizeFlowNode(...)` sizes a node from its text; `isStoreHot(db)` / `storePortLabel(name)`
are the store helpers.

## Item A — collapse ALL project nodes into ONE "PROJECTS" node
Current: ~14 individual `type:"project"` nodes in a left column, each with a
`FILESYSTEM → project` edge, positioned by a computed `projPitch` column (see the
"4. Project Nodes" block in `buildFlowGraph`).
Target: a SINGLE `type:"projects"` node that represents the whole set.
- Title `PROJECTS`, sub-label with total + active count (e.g. `14 · 3 active`).
  Active (accent border/glow) when any project is active, else dim.
- One `FILESYSTEM → PROJECTS` edge, active when any project is active.
- Attach `node.data = { projects: doc.projects, total: n, active_count: k }` so the
  tooltip/drawer can list every project (name + file_count + changes_60m, active
  ones highlighted). Add a `type === "projects"` branch to the tooltip/drawer that
  renders that list (reuse the existing per-project fields).
- Size the node from the title+sub-label via `sizeFlowNode` (~150×56). Place it on the
  LEFT, roughly where the column used to be (x ≈ cx - 540, y ≈ cy), vertically centered.
  It must NOT overlap the FILESYSTEM node (cx - 360) or the hub — verify with the
  bounding-box math.
- Remove the per-project node creation, the per-project edges, and the now-dead
  project-column layout math. Keep `sizeFlowNode`.

## Item B — revert DATA STORES back to the HORIZONTAL bar (with dots)
Current: `drawStoresStack` renders a vertical column of one row per store.
Target: a single HORIZONTAL rectangle (the layout the user liked — "with the dots")
with one labeled port per store along its TOP edge, each port drawn as a visible
circle/dot.
- Node: horizontal rect below the hub, x = cx, y = cy + 230, sized to fit all ports
  (~280 wide × ~64 tall, or wider if 5 labels need room). `id:"data-stores"`,
  `type:"datastores"`, `node.stores = doc.databases`.
- Ports: one per store, spread evenly along the top edge (store `port.dx` offsets +
  `port.dy = -h/2` for the top edge), each rendered as a small circle/dot + a short
  label via `storePortLabel(db.name)`. Hot stores (`isStoreHot`) get an accent dot +
  glow; idle stores get a dim dot. (This is the "with the dots" part — make the dots
  clearly visible.)
- Edges: hub → stores node (group center); each SERVICE (insights-board, hermes-gateway,
  scheme-board) → the SPECIFIC port dot it reads (reuse the existing `storePortLabel` /
  reader mapping and `findPortIdx`).
- Click/tooltip: show all stores (name + size_str + last_write_age_str, hot marked).
  Reuse the existing `type === "datastores"` tooltip branch (it already lists stores).
- Replace the `drawStoresStack` call in the render dispatch with a `drawStoresBar`
  (horizontal) — restore/port the pre-vertical port rendering. Remove dead references to
  the vertical stack (`rowW`/`rowH`/`STORE_*` constants) if unused.
