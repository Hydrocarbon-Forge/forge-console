## Issue 1 — C6 shows "0 active" always
Root cause (verified — confirm): `collector.py` `get_harnesses` hardcodes
`"active_sessions": 0` for `harness-c6`.
Fix: derive it from the hermes state db (read-only, additive; DB is at
`~/.hermes/state.db` — same dir as the existing `HERMES_DIR` constant):
- "active" = sessions with real recent message activity: count DISTINCT
  `messages.session_id` where `messages.timestamp > now - 300` (5-minute window).
  Tables: `sessions(id, user_id, chat_type, ...)`, `messages(id, session_id,
  role, timestamp, ...)`. Keep it cheap: one `SELECT COUNT(DISTINCT session_id)
  FROM messages WHERE timestamp > ?` — that's it, no joins needed.
- Add a `last_active_s` field too (seconds since the newest message, `SELECT
  MAX(timestamp) FROM messages`; null when no messages) — useful for the UI and
  for verifying.
- `active_sessions` = the count above; keep `running` as the process-alive check
  (unchanged). Any failure (missing db, locked, exception) → `active_sessions: 0`,
  `last_active_s: None` — never raise.
- Also update `subtasks`: count of rows in `session_turn_leases` (if that table
  exists and is readable; else keep 0) — optional, best-effort.
Verify live: while a session is actively chatting, `/api/flow` `harness-c6`
shows `active_sessions >= 1`; ~5 min after the last message it decays back to 0.

## Issue 2 — C6 node lit + moving dots when idle
Root cause (verified — confirm): `web/app.js` line ~2143:
`const active = h.active_sessions > 0 || h.running;` — for C6, `running` is true
whenever the gateway process is alive (always), so the node is always lit and its
hub edge carries density/dots even when nothing is being sent.
Fix: for the C6 harness node specifically, gate the "active/lit + dot-flow" state
on ACTIVITY, not process liveness: `active = h.running && (h.active_sessions > 0
|| h.last_active_s < 300)` — i.e. lit when alive AND recently active (or
currently active). The other three harnesses keep their existing semantics
(they already key off real session/process presence; don't change them).
- Node face subline: when `running` but not recently active, show e.g.
  `idle` (dim) instead of `0 active` — the tooltip can keep the precise fields
  (`last active: Xs ago`).
- The hub edge: density/dots only while active by the definition above; idle =
  dim edge, no dots (consistent with the graph's no-dot-when-idle rule).
Verify: while chatting, the C6 node is lit with dots and `N active`; wait/after
inactivity it dims to idle and the dots stop.

## Issue 3 — horizontal scrollbar on the projects hover tooltip
The `#flow-tooltip` (`.flow-tooltip`, style.css ~line 1239) has `max-width: 260px`
but its content (project rows / harness KPI rows with long mono strings) is wider
than 260px, so a horizontal scrollbar appears inside the hover box.
Fix: `.flow-tooltip` (and `.canvas-tooltip`/`.chart-tooltip` if they share the
problem): `overflow: hidden` (never scroll — a hover tooltip should not scroll),
plus `word-break: break-word; white-space: normal;` so long labels wrap instead
of overflowing. If the projects tooltip lists many rows and gets tall, cap it
with `max-height: 240px; overflow-y: auto;` (vertical scroll only). Keep position
behaviour as-is.
Verify (live browser): hover the PROJECTS node — tooltip shows, NO horizontal
scrollbar (confirm by measuring `tip.scrollWidth <= tip.clientWidth`), content
wraps instead of being clipped; same for the harness tooltip.
