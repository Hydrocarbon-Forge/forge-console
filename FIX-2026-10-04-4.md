## Item A — KPI block stuck on c6 numbers for the other 3 sources
Symptom (reproduced live in a browser): the USAGE SOURCE picker counts are correct and
distinct (c6 8.6M, opencode 2.5M, claudecode 3.6M, antigravity 4.3M, all 18.9M) —
`updateSourcePickCounts` is fine. But the KPI TOKENS card shows **8.6M for every
single source** and 18.9M for all.
ROOT CAUSE (diagnosed — verify): `renderInsightsKPIs` does
`s = getActiveSourceData()`, then
`billed = s.billed_tokens !== undefined ? s.billed_tokens : data.summary.billed_tokens || 0`
(and the same pattern for sessions/messages/tools/cost). For opencode/claudecode/
antigravity, `s` has no top-level `billed_tokens`, so the KPI silently falls back to
c6's summary (8.6M) for ALL four single sources. "all" works because
`buildMergedAllData` sets those fields explicitly.
FIX — compute per-source KPI values explicitly instead of the fallback-to-summary
pattern:
- c6: as today (summary fields).
- opencode / claudecode / antigravity:
  - billed tokens = `Σ models[*].billed_tokens` (same number as the picker count —
    the KPI and the pick bar must always agree).
  - sessions = `s.sessions` (present) or count of models.
  - cost = `s.total.reported_cost_usd` (0 when unreported — show "—/unreported").
  - messages/tools/api_calls: these sources don't report them — show "—" (not 0, not
    c6's numbers). Remove the silent c6 fallback for fields a source doesn't report.
- all: `buildMergedAllData` (already sums the right things; keep).
- The picker bar counts (`updateSourcePickCounts`) and the KPI TOKENS card must show
  the SAME number for the active source — derive both from one helper
  (e.g. `sourceBilledTokens(src)` / `sourceCostUsd(src)`) so they can't drift.
- Show the token breakdown the user asked for: under each source's KPI (sub-line) and
  for the pick bar (tooltip on hover, `title` attr) show input/output/cache-read
  from `total` when available — e.g. `8.6M billed · 0 in / 0 out (c6)` or
  `2.5M billed (14 in / 2.1 out / 0 cached)`. For c6 use whatever the summary offers
  (it may only have billed; then show just billed). Keep it short and monospace.
VERIFY (headless, in the browser): with days=7, clicking each source shows KPI TOKENS =
the pick-bar count for that source (distinct per source), cost matches the source's
reported cost, and "—" appears for unreported fields. "all" still sums.

## Item C — static cache headers (tiny, server.py)
`handle_static` serves `app.js`/`index.html`/css with no cache headers, so users keep
seeing OLD versions after fixes (this is very likely why the last round of fixes
looked "not applied" to the user's browser). Add response headers:
- `app.js`, `index.html`, and any `.html`: `Cache-Control: no-cache` (revalidate).
- `styles.css` and other assets: `Cache-Control: max-age=300` is fine, but also send
  `Cache-Control: no-cache` for .js and .html specifically.
No other server changes.
VERIFY: `curl -sI http://127.0.0.1:8903/app.js` shows the Cache-Control header.
